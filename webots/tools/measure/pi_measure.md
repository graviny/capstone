# Pi 측정 결과 (2026-10-28)

Raspberry Pi + Camera Module 3로 통신 성능, 이미지 크기, 라벨 판독 거리, 시야각을 잰 결과예요.
원본 로그는 `~/aga_measure/results.log`, 측정 스크립트는 `~/aga_measure/measure.sh`예요.

## 측정 환경

| 항목 | 내용 |
|---|---|
| 장비 | Raspberry Pi (Wi-Fi), Windows 노트북 |
| 카메라 | Camera Module 3 **표준형** (센서 imx708, 와이드 아님) |
| 네트워크 | 휴대폰 핫스팟(Galaxy S20 5G, 2.4GHz 채널 1)에 Pi와 노트북을 함께 연결 |
| Pi 링크 | 72.2Mbps (노트북 쪽 링크는 117~144Mbps) |
| JPEG 품질 | 80 (프로젝트 기본값과 동일) |

## 요약

| 항목 | 결과 |
|---|---|
| 통신 | 손실 0~2%, 평균 지연 14~18ms, 처리량 22~28Mbps. 혼잡 시 약 16% 감소 |
| 이미지 크기 | 720p 약 60~140KB, 480p 약 27~68KB (장면에 따라 2배 이상 차이) |
| 라벨 판독 | AprilTag(7cm)는 2.6m까지 판독, 2.9m부터 실패. 글자와 QR은 미측정 |
| 시야각 | 720p 가로 66° / 480p 가로 약 52° (공식 참고값 기반, 실측 아님) |

## 1~3. 통신

노트북에서 Pi(10.129.90.181)로 측정했어요. ping 100회, 20MB 다운로드 3회, `netsh` 신호 순이에요.
5m는 공간이 없어서 2m로 대체했어요. Pi 쪽 신호 세기(dBm)는 조건별로 재지 않았어요.

| 조건 | 손실 | 평균 지연 (최소/최대) | 처리량 3회 (Mbps) | 평균 | 신호 | 수신 링크 |
|---|---|---|---|---|---|---|
| 1m (기준) | 2% | 15ms (7/76) | 29.0 / 25.9 / 27.8 | 27.6 | 96% | 144.4 |
| 2m | 0% | 18ms (7/139) | 21.5 / 21.3 / 23.1 | 22.0 | 93% | 117 |
| 금속 선반 뒤 | 0% | 16ms (6/67) | 24.1 / 22.6 / 24.1 | 23.6 | 93% | 144.4 |
| 벽 너머 (화장실) | 0% | 14ms (7/37) | 27.0 / 27.1 / 27.2 | 27.1 | 93% | 144.4 |
| 혼잡 (1m + 동영상) | 0% | 14ms (5/58) | 22.5 / 23.4 / 24.0 | 23.3 | 98% | 130 |

**해석할 때 주의할 점**
- 조건 간 차이는 대부분 오차 범위예요. 같은 조건 안에서도 처리량이 2~3Mbps씩 흔들려요.
- 의미 있는 차이는 혼잡 시 감소(27.6 → 23.3Mbps, 약 16%) 하나뿐이에요.
- 노트북만 옮겼고 Pi는 핫스팟 바로 옆(약 -29~-34dBm)에 있었어요. 그래서 장애물과 거리 결과는 노트북↔핫스팟 구간만 반영해요.
- 처리량 상한은 Pi 쪽 링크(72.2Mbps)가 만들었을 가능성이 커요.
- 실제 창고에서 Pi가 공유기에서 멀거나 선반 뒤에 있으면 이보다 낮을 수 있어요. 이 경우는 Pi를 옮겨서 다시 재야 해요.

## 4. 이미지 크기

JPEG 품질 80, 장면마다 10장씩 찍어 평균을 냈어요. 첫 장은 자동 노출이 안정되기 전이라 버렸어요.
카메라와 물건 사이 거리(계획은 0.78m)는 확인하지 못했어요.

| 장면 | 720p 평균 (최소~최대) | 480p 평균 (최소~최대) |
|---|---|---|
| 단순 (빈 벽 + 박스 + 컵) | 62.5KB (62.0~62.9) | 27.0KB (26.9~27.1) |
| 복잡 (잡동사니) | 124.6KB (123.9~125.8) | 58.9KB (58.7~59.2) |
| 중간 (그림 가방 + 컵 + 박스) | 140.6KB (140.1~140.9) | 68.4KB (68.3~68.6) |

- 범위는 720p 약 60~140KB, 480p 약 27~68KB예요. 480p는 720p의 약 43~48% 크기예요.
- 복잡도는 물건 개수보다 화면 전체의 질감과 색 변화가 좌우해요. 큰 그림이 배경을 채운 "중간" 장면이 가장 컸어요.
- 실제 창고의 책장이나 선반에 가까운 값은 125~140KB 구간으로 보는 게 안전해요.
- 이론상 이미지 전송 상한은 처리량 22Mbps 기준으로 초당 약 20장(140KB)에서 44장(62KB)이에요. 오버헤드는 포함하지 않았어요.

## 5. 라벨 판독 거리

휴대폰 화면에 tag36h11 AprilTag(한 변 7cm)를 띄우고, OpenCV로 자동 판독했어요. 화면 밝기를 낮춘 뒤 측정했어요.

| 거리 | 720p | 480p |
|---|---|---|
| 약 1.4m (찍힌 크기로 환산) | 성공 (한 변 48.5px) | 성공 (32.0px) |
| 2.6m | 성공 (30.3px) | 성공 (20.0px) |
| 2.9m | 실패 | 실패 |
| 3.2m | 실패 | 실패 |

- 판독 한계는 2.6~2.9m 사이예요. 720p와 480p의 한계가 같아서, 해상도보다 칸이 뭉개지는 정도가 한계를 정한다고 볼 수 있어요.
- 신뢰 거리로는 한계의 약 20%를 뺀 2.3m 안팎을 권해요(판단한 값이고 측정값은 아니에요).
- 태그 크기에 거의 비례한다고 가정하면 4~5cm 태그는 약 1.3~1.6m, 14cm 태그는 약 4.6m예요. 이건 추정이고 실측하지 않았어요.
- 화면 밝기가 높으면 흰 칸이 번져서 판독이 안 돼요. 처음에 같은 태그가 가까이서도 실패했고, 밝기를 낮추자 읽혔어요.
- 거리는 사용자가 잰 값이에요(1.4m만 찍힌 크기에서 환산). 휴대폰 화면 기준이라 인쇄물은 결과가 다를 수 있어요.
- 글자 라벨("BLUE-07")과 QR은 아직 측정하지 않았어요.

## 6. 시야각

줄자가 없어서 실측하지 않았어요. 카메라 모델의 공식값에서 계산했어요.

| 해상도 | 가로 | 세로 |
|---|---|---|
| 1280×720 (16:9) | 66° | 약 40° |
| 640×480 (4:3) | 약 52° | 약 40° |

- 480p는 같은 장면을 두 해상도로 찍어서, 세로 시야는 같고 가로만 720p의 75%로 잘리는 것을 사진으로 확인했어요.
- 실측이 필요하면 카메라에서 벽까지 거리와 화면에 보이는 가로 폭을 재서 계산하면 돼요(A4 종이 가로 29.7cm를 줄자 대신 쓸 수 있어요).
