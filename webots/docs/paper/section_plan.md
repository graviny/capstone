## 1. Abstract (마지막에 작성, 150–180단어)

RSS 논문 초록은 같은 순서로 쓴다 [원문]. 기존 연구의 **구체적 가정을 한 문장으로 지목**하고 자기 문제로 넘어간다. 예: p005 "In contrast to most existing work that assumes perfect positional information…", p118 "the typical TAMP problem formulation assumes full observability…".

| 문장 | 내용 | 우리 초록에 넣을 것 |
|---|---|---|
| 1 | 응용과 필요 | WES가 적치·피킹·확인 작업을 다중 로봇에 실시간 배정한다 |
| 2 | 기존 가정과 한계 | 배정 연구는 재고 기록이 정확하다고 가정하지만, 사람의 기록 없는 이동·반출로 기록은 자주 틀린다 |
| 3 | 질문 / 가설 | 이런 창고에서 학습한 배정 정책이 처음 보는 날짜의 주문에도 일반화되는가 (H1) |
| 4 | 방법 | 실제 WMS·WES 코드를 쓰는 고속 시뮬레이터에서 선형 점수 정책을 CEM으로 학습한다. 실제 신발 창고 주문 데이터를 **날짜 단위로 학습/시험 분할**하고, Webots로 검증한다 |
| 5 | 예비 결과 | 학습 날짜에서는 리드타임 약 7% 감소, 처음 보는 날짜에서는 차이 없음 → 시드 분할은 개선을 과대평가한다 |
| 6 | 계획과 통찰 | H2–H5를 가르는 실험(학습 날짜 수, 특징, 오류율, 시뮬레이터 차이)으로, 어떤 결과가 나와도 일반화 실패의 원인을 밝힌다 |

**쓰지 말 것**

- "학습이 기본 WES보다 11–22% 낫다"를 대표 결과로 쓰지 않는다. 학습 날짜에서 잰 값이라 과적합이 섞여 있다.
- 결과 수치는 1단계에서 "preliminary"라고 밝힌다.

## 4. Problem (1.4쪽: 형식화 + 가정 + 방법)

RSS 논문은 형식 모델, 명시적 가정, "Problem 1" 진술 순서로 쓴다 [원문]. 참고할 형식은 다음과 같다.

- p039: 이벤트 기반 MDP로 물류 스케줄링을 정의
- p118: belief-state MDP
- p181: "Necessary Assumptions" 소절을 따로 둠

### 4.1 창고와 관측 모델 (0.5쪽)

- **창고:**
  - 랙 칸 집합 `𝒮`, 로봇 `ℛ`(8대), 출고 레인, 입고 대기칸
  - 작업 종류: PUTAWAY, PICK, RELOCATE, VERIFY
  - 출고 트럭은 지역별 900초 마감
- **상태:** 실제 재고 `x_t : 𝒮 → SKU ∪ {∅}`와 WMS 기록 `x̂_t`를 구분한다.
- **관측:** WES는 `x̂_t`, 작업 대기열, 로봇 보고, 이벤트(SHORT_PICK, ITEM_MISMATCH, DESTINATION_OCCUPIED, OBSERVATION_RESULT)만 본다.
  - 불일치는 **로봇이 칸에 도착해 라벨을 읽을 때만** 드러난다.
  - 이 형태는 RSS 2026 p042의 "blockages discovered only when a robot arrives"와 같다 [원문].
- **결정:** 매 결정 시점 `k`에 시작 가능한 작업과 놀고 있는 로봇을 짝짓는다(한 작업·한 로봇은 한 번만).
- **불일치 과정:**
  - S1 이동, S2 반출: 마크된 포아송 과정
  - S3 적치 목적지 점유: 적치 작업에 조건부로 생김
  - 정의는 `research_protocol.md` §1과 맞춘다.
- **목적:** 주문 리드타임 평균. 미완료 주문은 에피소드 끝 시각으로 절단해 포함한다.
  - 끝낸 주문만 평균하면 어려운 주문을 미루는 정책이 유리해 보이기 때문이다.
- **Problem 1.** 처음 보는 날짜의 주문 분포 `𝒟_test`에서 기대 리드타임을 최소화하는, 관측만 쓰는 배정 정책 π를 찾는다.

### 4.3 Approach (0.7쪽)

- **점수 정책:** `S(τ, r) = wᵀφ(τ, r)`. 점수가 높은 짝부터 탐욕적으로 고른다.
  - 특징 표(dist, busy, eta, 작업 종류, age, slack, truck_here, lane_fill, buffer_fill)는 `main.tex` 표 1을 그대로 쓴다.
  - 선형 정책 + CEM의 선례: Szita & Lőrincz 2006 [서지]
  - "새 학습 알고리즘"이라고 주장하지 않는다.
- **고속 시뮬레이터:**
  - 같은 scenario·WMS·WES 코드를 쓰고, 이동만 "경로 길이/속도 + 2초 + 양보 1초 × 우선 로봇 수"로 단순화했다.
  - 이전 입력의 Webots 51회 보정 수치를 현재 v3의 근거로 사용하지 않는다. v3 개발 점검에서 주 지표의 정책 순위가 뒤집혔다 (`artifacts/engine_gap_v3/policy_comparison_primary.md`).
  - 경량은 후보 학습에 사용한다. 검증 날짜의 Webots로 정책을 선택하고 보류 시험 날짜 Webots로 최종 평가한다.
- **학습:**
  - CEM: 후보 24, 상위 6, 15회 반복
  - 비용: `0.5·L_order + 0.5·L_unit + 100·N_missed`
  - 학습 시드 5개
- **평가 프로토콜 (이 논문의 핵심 방법):**
  - 날짜를 학습 / 검증 / 시험으로 **겹치지 않게** 고정한다.
  - 평가 단위는 날짜다.
  - 날짜별 쌍대 차이(방법 − 팀 기본 WES)에 날짜를 재표집한 부트스트랩 95% CI를 붙인다. 근거: Agarwal 등 2021 (`research_protocol.md`)
  - 학습 시드 간 분산도 보고한다. 근거: Henderson 등 2018 [서지]

## 5. Experiment (1.7쪽: 질문 → 설정 → 예비 결과 → 계획)

RSS 논문은 "다음 질문에 답하도록 설계했다"로 시작해 Q1–Qn을 둔다(p027, p098, p039, p181) [원문]. 다음 세 가지도 대부분 들어간다.

- **시나리오 파라미터 범위 표** (p039 Table I)
- **성격별로 묶은 비교군** (p039: offline / online)
- **분포 밖 일반화 시험** (p101: 더 큰 문제, 다른 팀 구성, 다른 분포)

### 5.1 질문 (가설과 1:1)

| Q | 질문 | 지지되면 보일 것 | 반증되면 보일 것 |
|---|---|---|---|
| Q1 (H1) | 학습 정책이 처음 보는 날짜에서 비교군보다 리드타임을 줄이는가 | 시험 날짜 쌍대 차이의 CI가 0보다 작음 | CI가 0을 포함 |
| Q2 (H2) | 학습 날짜 수를 늘리면 새 날짜 개선이 커지는가 | 날짜 수 {2, 6, 18, 48, 96}에 따라 일반화 차이가 줄어듦 (설계 근거: Cobbe 등 2019) | 날짜를 늘려도 평평함 → H3로 |
| Q3 (H3) | 주문 단위 특징(주문 크기, 남은 줄 수, 주문 나이)을 넣으면 개선이 생기는가 | 같은 예산에서 개선이 생김 | 변화 없음 |
| Q4 (H4) | 이득이 기록 불일치와 관련 있는가 | 오류율이 클수록 학습 이득이 커짐. 학습이 실제 재고를 아는 오라클과의 격차를 줄임 | 학습 조건(오류 유무)과 무관 |
| Q5 (H5) | 경량 시뮬레이터 결론이 Webots에서 유지되는가 | 방법 순위·쌍대 차이 방향이 일치 (관련: RSS 2026 p090, 싼 시뮬레이터로 평가를 보완하는 문제) | 불일치 → 경량 결과의 적용 범위를 제한 |

### 5.3 예비 결과 (이미 있는 것만, 표 1개 + 그림 1개)

**표: 시드 분할 vs 날짜 분할**

- `template/main.tex`의 과적합 표: 2일 / 3일 학습 × 같은 날짜 / 새 6일 × 경량 / Webots
- 한 줄 해석: "시드는 입고와 작업자 오류만 바꾸고 출고 주문은 그대로 두므로, 시드 분할 시험은 학습한 주문 패턴에서 평가된다."

**보조 사실 1–2개**

- 상자 단위 리드타임은 방법 간 거의 같다(405–423초). 개선은 처리량이 아니라 **주문을 끝내는 순서**에서 나온다 (`main.tex` Webots 표).
- Webots 오류 조건에서 무오류 학습 가중치가 오류 학습 가중치보다 나았다(−113초 대 −57초). 이 사실이 H4를 세운 이유다.

**주의:** 다음 값은 학습 날짜에서 잰 값이라 대표 결과로 쓰지 않는다. 쓰려면 "학습 날짜 내 결과"라고 밝힌다.

- 경량 7.4% 개선
- Webots 11–22% 개선

## 6. Conclusion (0.3쪽)

세 단락으로 쓴다.

1. **가설별 정리:** H1–H5 각각을 지지 / 반증 / 진행 중으로 한 줄씩 쓴다. 1단계에서는 "예비 결과는 H1을 지지하지 않으며, H2–H5로 원인을 가린다"가 된다.
2. **결과와 무관한 통찰:** "운영 데이터로 학습한 배정 정책은 시드가 아니라 날짜로 나눠 평가해야 한다." 이 교훈은 결과가 어느 쪽이어도 남는다. RSS 2027 리뷰 기준 "Value of Hypothesis"에 해당한다.
3. **한계와 다음 단계:**
   - 실물 로봇 없음
   - 오류율은 합성(민감도로 다룸)
   - 창고 레이아웃 한 종류
   - 선형 정책
   - 2단계 Extension Charter에서 확장할 실험

RSS 2024–26 논문 다수는 Limitations를 별도 절로 두었다(p027, p098, p099, p116, p183, p042) [원문]. 1단계는 공간이 부족하니 Conclusion 안에 넣고, 2단계 8쪽판에서 절로 분리한다.
