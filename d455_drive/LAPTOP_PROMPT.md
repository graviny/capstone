# 노트북 AI에게 줄 프롬프트

아래 `---` 사이를 그대로 복사해서 노트북의 AI에게 주면 된다. `<...>` 부분은 채워서 줄 것.

---

## 프로젝트 개요

천장에 수직으로 내려다보도록 설치한 Intel RealSense **D455**로 바닥 위의 소형 RC카(Adeept PiCar-B2, Raspberry Pi)를 인식하고, 카메라 화면에서 클릭한 목표 지점까지 **A\*** 경로로 주행시키려고 한다.

역할 분담:
- **노트북(너가 만들 부분)**: D455 영상 획득 → AprilTag로 로봇 위치/방향 추정 → 깊이로 장애물 지도 생성 → A* 경로 계산 → 경로 추종 제어(Pure Pursuit) → PiCar에 속도/조향 명령 전송
- **PiCar(이미 구현됨)**: 명령을 받아 모터/조향 실행 + 전방 초음파로 돌발 장애물 감속/회피. PiCar는 **자기 위치를 모른다.** 위치 기반 제어는 전부 노트북 몫이다.

Python 3로 작성하고, 사용 라이브러리는 `pyrealsense2`, `opencv-python`(ArUco 모듈의 `DICT_APRILTAG_36h11` 또는 `pupil-apriltags`), `numpy`, `websockets`(asyncio) 정도로 한다.

## 로봇(PiCar-B2) 특성 — 경로 계획·제어에 반드시 반영

- **앞바퀴 조향 + 뒷바퀴 구동(자전거 모델).** 제자리 회전 불가, 최소 회전 반경 있음 → 격자 A*의 꺾인 경로를 그대로 따라갈 수 없다. 경로 스무딩 필수, 좁은 공간에서 실패가 잦으면 Hybrid A*(조향각 이산화 + 최소 회전 반경 반영) 고려.
- 조향 명령 범위: **-30 ~ +30, + = 왼쪽** (실차 확인 완료: +steer = 왼쪽, +speed = 전진)
- 조향 명령 ≈ 실제 앞바퀴 각도(실측: 명령 30 → 약 30°). Pure Pursuit로 계산한 바퀴 각도 δ(도)를 그대로 `steer`로 보내면 된다. 다만 변환 비율(`steer_cmd = δ × k`, 기본 k = 1.0)은 config로 빼서 실주행에서 조정 가능하게 할 것.
- 속도 명령: **-100 ~ 100 (%)**, 음수 = 후진. PiCar에서 최대 60%로 제한됨. 실제 m/s 및 움직이기 시작하는 최소값은 `<모름>`.
- 휠베이스: 10.5cm. 최대 조향 시 회전 반경: 이론상 약 0.18m(0.105 / tan 30°), **실측 반지름 약 0.32m** (speed 30, steer 30 기준 — 바퀴 미끄러짐 때문에 이론값보다 큼). 경로 계획·Hybrid A*·장애물 팽창에는 실측값 0.32m(여유 두면 0.35m)를 최소 회전 반경으로 사용하고 config로 뺄 것. 속도가 빠르면 더 커질 수 있다.
- 센서는 **전방 초음파 1개**뿐. 후진 방향은 보호되지 않는다.

## PiCar 통신 프로토콜 (WebSocket, JSON 텍스트)

노트북 → PiCar:
```json
{"type":"cmd","speed":40,"steer":-12,"seq":123}
{"type":"stop"}
{"type":"ping","t":1712.3}
```
- `cmd`는 **10~20Hz로 계속 보내야 한다.** 0.5초 동안 안 오면 PiCar가 정지한다(워치독). 정지 상태를 유지하려면 `speed:0`을 계속 보내거나 그냥 안 보내면 된다.
- `seq`는 선택. 상태 메시지의 `last_seq`로 되돌아와서 지연 확인에 쓸 수 있다.
- 제어 클라이언트는 1개만 허용(새로 접속하면 기존 연결이 끊김).

PiCar → 노트북:
```json
{"type":"status","state":"normal","avoid_phase":null,"dist_cm":87.4,"speed":40.0,"steer":-12.0,"last_seq":123,"battery_v":7.9}
{"type":"event","event":"avoid_start","dist_cm":16.2}
{"type":"event","event":"avoid_done","result":"ok","avoid_dir":"left","scan_left_cm":80.1,"scan_right_cm":21.0}
{"type":"pong","t":1712.3}
```
- `status`는 10Hz. `state`: `idle`(명령 없음) / `normal` / `slow`(전방 18~35cm, 자동 감속 중) / `avoiding`(회피 중).
- `speed`, `steer`는 안전 계층을 거쳐 실제로 적용된 값.
- 전방 18cm 이내에서 전진 명령이 오면 PiCar가 **자율 회피**를 한다(약 2.5~3초, 그동안 노트북 명령 무시): 정지 → 좌우 스캔 → 후진 → 빈 쪽으로 선회.
- `avoid_done.result == "blocked"`: 양쪽이 막혀 후진만 하고 멈춘 상태.

## 구현해야 할 것

1. **카메라 & 보정**
   - D455 컬러(+깊이, `align`으로 컬러에 정렬) 스트림, 30fps.
   - 바닥 기준 태그로 **픽셀 ↔ 바닥 평면 좌표(m) 호모그래피**를 구해 파일로 저장/로드(카메라가 고정이라 한 번만).
2. **로봇 포즈 추정**
   - 로봇 태그 검출 → 태그 중심을 바닥 좌표로 변환 → 오프셋 보정해 로봇 기준점 (x, y), 태그 방향으로 헤딩 θ.
   - 태그가 바닥보다 높이 있으므로(차체 높이) 시차 보정을 하거나, `solvePnP`로 3D 포즈를 구한 뒤 바닥 좌표계로 변환.
   - 간단한 필터(지수 평활 또는 칼만)로 안정화. 태그가 0.5초 이상 안 보이면 정지 명령.
3. **장애물 지도**
   - 깊이에서 바닥 평면보다 일정 높이(예: 3cm) 이상 솟은 점을 장애물로 → 격자(5cm 셀) 점유 지도.
   - **로봇 자신 영역은 제외**(태그 위치 주변 로봇 크기만큼 마스킹).
   - 로봇 반경 + 여유만큼 **장애물 팽창(inflation)**.
   - 매 프레임 갱신하되 노이즈 제거(몇 프레임 누적/모폴로지).
4. **경로 계획 (A\*)**
   - 시작: 현재 로봇 셀, 목표: 화면에서 클릭한 점(픽셀 → 바닥 좌표 → 셀).
   - 8방향, 유클리드 휴리스틱. 결과 경로를 line-of-sight로 단순화 후 스무딩, 일정 간격으로 재샘플링.
   - **재계획 조건**: 로봇이 경로에서 일정 거리 이상 이탈 / 경로 위에 새 장애물 / PiCar의 `avoid_done` 수신 / 목표 변경.
5. **경로 추종 (Pure Pursuit)**
   - lookahead 거리(속도에 비례, 예: 0.25~0.5m)의 경로점을 목표로 조향각 계산 → ±30°로 제한, 부호 규칙(+ = 왼쪽) 주의.
   - 곡률이 클수록, 목표에 가까울수록 감속. 목표 반경(예: 10cm) 안에 들어오면 정지.
   - 20Hz로 `cmd` 전송.
6. **PiCar 상태 처리**
   - `state == "avoiding"`인 동안엔 명령을 보내도 무시되므로 계속 보내되, 끝나면(`avoid_done`) 현재 위치에서 재계획.
   - `avoid_done.result == "blocked"`가 짧은 시간 안에 반복되면(예: 10초 내 3회) 그 방향을 임시 장애물로 지도에 표시하고 재계획, 그래도 안 되면 정지 후 사용자에게 알림.
   - `battery_v < 6.5` 경고 표시.
7. **GUI (OpenCV 창이면 충분)**
   - 컬러 영상 위에 로봇 위치/방향, 장애물(반투명), A* 경로, lookahead 점, 목표점 표시.
   - 마우스 클릭 = 목표 지정, `space` = 정지/재개, `q` = 종료(정지 명령 보내고 종료).
   - PiCar 상태(state, dist_cm, speed, steer, 배터리, 통신 지연) 표시.

## 구조 / 요구 사항

- 모듈 분리: `camera.py`, `calib.py`, `localization.py`, `obstacle_map.py`, `planner.py`(A*/스무딩), `controller.py`(Pure Pursuit), `picar_client.py`(WebSocket, 재접속 포함), `main.py`. 파라미터는 `config.yaml` 하나에.
- 카메라/인식 루프와 통신 루프가 서로 막지 않게(asyncio 또는 스레드).
- 어떤 예외가 나도, 종료할 때도 **반드시 정지 명령**을 보낼 것.
- PiCar 없이도 시험할 수 있게 PiCar 서버 흉내 모드 또는 기록 영상 재생 모드가 있으면 좋다. (PiCar 쪽은 `python3 server.py --dry-run -v`로 하드웨어 없이 서버만 띄울 수 있다.)

## 개발 순서 (단계마다 동작 확인 후 다음으로)

1. D455 영상에 로봇 태그 검출 + 바닥 좌표/헤딩 표시
2. PiCar에 접속해 키보드로 speed/steer 원격 조종 (부호/방향 확인, 최소 속도·회전 반경 측정)
3. 장애물 없이 클릭한 점까지 Pure Pursuit로 주행
4. 깊이 장애물 지도 + A* + 스무딩 경로 추종
5. `avoid_done` 처리, 재계획, 반복 실패 처리

모르는 값(위 `<...>` 중 비어 있는 것)은 추측하지 말고 config에 두고 나에게 물어봐.
