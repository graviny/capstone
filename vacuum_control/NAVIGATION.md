# D455로 목표점 이동하기

현재 약 1m 높이의 시험 설치와 이후 약 3m 높이의 시연 설치에서 같은 프로그램을
사용합니다. 설치를 바꿀 때 **바닥 치수와 카메라 좌표를 다시 보정**합니다.
실제 카메라 높이를 입력하는 방식이 아니라, 실측한 바닥 사각형 네 점으로
카메라의 위치·기울기를 계산합니다. WES 없이 실행할 수 있습니다.

인쇄한 바닥 ID 10–13으로 클릭 없이 보정하려면 [바닥 마커 설치 안내](FLOOR_MARKER_SETUP.md)를
보세요. 아래 절차는 종이 마커 없이 시험할 때 사용하는 수동 보정입니다.

## 목표를 찍지 않고 전방 장애물 우회 시험

D455를 바닥을 향해 고정하고 로봇 위 ID 0의 화살표를 실제 정면에 맞춥니다.
이 모드는 바닥 태그 없이 깊이 영상으로 바닥 면을 추정합니다. 로봇의 시작 방향을
따라 최대 1.2m 앞에서 지도상 통행 가능한 지점을 자동으로 정합니다. 오른쪽 지도를
클릭하면 원하는 목표로 바꿀 수 있습니다. 카메라나 출발 위치를 바꾸면
`전방 다시 읽기`를 누르세요.

```powershell
.\.venv-camera\Scripts\python.exe navigation_app.py --forward-avoid
```

미리보기에서 빈 바닥의 파란 직선과 상자를 놓은 뒤 바뀌는 경로를 비교합니다.
실물은 `--forward-avoid --drive`로 실행해 토큰을 입력하고 `실물 주행 시작`을
누릅니다. 전방 경로가 막히면 정지 요청을 먼저 보냅니다. 정지 명령에 응답이 오고
태그 위치와 방향이 안정되면 현재 위치에서 같은 목표까지 새 경로를 계산합니다.
새 경로가 확보되면 그 경로로 자동 재출발합니다. 속도는 최대 0.05m/s입니다.
첫 실물 우회 시험은 상자를 경로 중간에 미리 놓고 진행하세요. 바닥 깊이나
로봇 태그가 끊기면 정지하며, 다시 시작하려면 시작 버튼을 눌러야 합니다.

재계산 시간을 재려면 미리보기에 `--measure-replan`을 붙입니다. 파란 경로가 생긴
뒤 로봇을 세워 둔 채 경로 중간에 상자를 놓고 하단의 측정값을 확인하세요.
`runtime/replan_timing_stop_first.csv`에 프레임 대기, 지도 갱신, 경로 검사, 정지 확인
대기, A*·경로 단순화, 프레임 수신부터 재계산까지의 시간(ms)을 기록합니다. 처음 만든 경로는
측정에서 제외됩니다. 깊이 장애물로 막힌 경우 `depth_obstacle`, 다른 차단은
`other_blockage`로 표시됩니다. 결과가 `no_path`이면 우회로를 찾지 못한 시간입니다.
프레임 시각은 정렬된 깊이와 컬러가 앱에 전달된 시각입니다. 물체가 실제 등장한
순간부터 카메라가 그 프레임을 받기까지의 시간과 바퀴 정지 시간은 별도 측정입니다.
미리보기에는 실제 청소기의 정지 응답을 기다리는 시간이 포함되지 않습니다.

## ID 10 목표로 이동과 우회 시험

바닥 위쪽에는 ID 10·11을 평평하게 두고, 로봇 위에 ID 0을 고정합니다.
`--tag-test`를 붙이면 두 바닥 태그의 깊이로 바닥 면을 잡고 ID 10의 중심을
목표로 설정합니다. ID 11은 주행 화면 안에 계속 보이게 두세요.

```powershell
.\.venv-camera\Scripts\python.exe navigation_app.py --tag-test
```

1. 빈 바닥에서 `직선 경로 준비`와 파란 선을 확인합니다.
2. 출발 위치를 유지하고 직선 경로 중간에 작은 상자를 둡니다. 지도에서 상자와
   `우회 경로 준비`가 보이는지 확인합니다. 통로가 좁으면 `경로 없음`이 정상입니다.
3. 실물 시험은 실행 명령에 `--drive --ip` 뒤에 실제 청소기 IPv4 주소를 붙이고 토큰을 입력합니다.
   첫 이동 후 정지한 상태에서 로봇을 출발점에 돌려놓고 상자를 둔 다음, 경로를
   확인한 뒤 두 번째로 시작을 누릅니다. Esc로 정지할 수 있습니다.

태그나 카메라 위치를 조정했다면 `태그 다시 읽기`를 누릅니다. 로봇 태그 표면의
깊이가 불안정하면 `--robot-marker-height`에 실측한 높이(m)를 지정하세요.
출발·목표·상자 주변 바닥이 충분히 보이도록 카메라와 물건 위치를 잡으세요.

## 1. 먼저 이동 명령 없이 실행

RealSense Viewer와 기존 `camera_demo.py` 등 D455를 사용하는 창을 먼저 닫습니다.
[README의 설치](README.md#windows에서-설치)를 마친 뒤 이 폴더에서 PowerShell을 실행합니다.

```powershell
.\.venv-camera\Scripts\python.exe navigation_app.py
```

기본 실행은 영상·위치·경로·제어값을 보여 주는 미리보기입니다.
토큰을 묻지 않으며 로봇에 접속하지 않습니다.
장치 없이 창을 시험하려면 `navigation_app.py --simulate`로 실행합니다.
모의 화면에는 합성 바닥·마커·장애물과 이동하는 가상 로봇이 표시됩니다.

## 2. 바닥과 아이패드 준비

1. 카메라를 고정하고, 화면에 온전히 들어오는 평평한 바닥 사각형을 테이프로
   표시합니다. 가로·세로를 줄자로 재세요. 구역 경계에는 로봇 중심이
   접근할 수 없는 여유 공간이 포함됩니다. 기본 로봇 반경 18cm + 여유 15cm입니다.
2. 아이패드의 ID 0 마커 중심을 청소기 중심 위에 놓고 화면을 수평으로 고정합니다.
   마커 그림의 `ROBOT FRONT` 화살표를 청소기의 실제 정면에 맞추세요.
   흰 여백과 검은 테두리 전체가 보여야 합니다. 화면 회전과 자동 잠금을 끄고
   상부 레이저 센서의 시야를 가리지 않게 배치합니다.
3. **바닥부터 아이패드 화면 표면까지의 높이**를 잽니다. 상단 `로봇 마커 높이(m)`는
   이 값입니다. D455의 바닥 높이 약 1m 또는 3m를 이 칸에 넣으면 안 됩니다.
   예를 들어 화면이 바닥에서 12cm라면 `0.12`입니다. 이 예시를 실측 대신 쓰지 마세요.

아이패드 표면은 반사 때문에 깊이값이 잘 안 나올 수 있습니다. 로봇 위치는
깊이값 대신 카메라 시선과 위에서 입력한 화면 높이 평면의 교차점으로 구합니다.
주변 바닥과 장애물은 D455 깊이 영상을 사용합니다.

## 3. 좌표 보정과 경로 확인

1. 상단에 `바닥 가로(m)`, `세로(m)`, `로봇 마커 높이(m)`를 입력합니다.
2. `바닥 네 점 지정`을 누르면 영상이 정지합니다. **바닥** 사각형의 모서리를
   영상 기준 **왼쪽 위 → 오른쪽 위 → 오른쪽 아래 → 왼쪽 아래** 순서로 클릭합니다.
   아이패드의 모서리를 클릭하는 것이 아닙니다. 왼쪽 위→오른쪽 위 변이 가로이고,
   왼쪽 위→왼쪽 아래 변이 세로입니다. 네 점은 실제 직사각형이어야 합니다.
   상단에 `바닥 점 0/4`가 표시되고 클릭할 때마다 숫자가 증가하며, 영상에
   주황색 점과 번호가 즉시 나타납니다. 검은 여백 밖의 실제 영상 안을 클릭하세요.
   점 지정 중에는 카메라 수신이 지연되어도 고정한 영상에 계속 표시할 수 있습니다.
3. 표시되는 추정 카메라 높이가 실측 설치 높이와 비슷한지 확인한 뒤
   `보정 저장`을 누릅니다. 잘못 클릭했으면 `바닥 네 점 지정`부터 다시 합니다.
4. 지도의 녹색 원과 방향 화살표가 실제 로봇의 위치·정면과 맞는지 확인합니다.
   바닥의 알려진 두세 위치로 로봇을 옮겨 좌표와 방향을 비교하세요.
5. 오른쪽 지도에서 통행 가능한 목표점을 클릭합니다. 파란 경로가 표시됩니다.
   `제어값 미리보기 시작`으로 계산값을 볼 수 있습니다. 기본 모드에서는 실제로
   움직이지 않으므로 로봇 위치도 그대로입니다.

흰색은 관측한 통행 영역, 진한색은 장애물, 회색은 미측정, 연분홍은 로봇 크기와
여유 거리를 고려해 접근을 막은 곳입니다. 미측정 구역을 가로질러 계획하지 않습니다.
지도 클릭 방식을 `장애물 사각형`으로 바꾸면 두 모서리를 클릭해 추가 금지 영역을
지정할 수 있습니다. 자동 깊이 인식이 어려운 물체를 미리 표시할 때 사용합니다.

보정 파일은 `runtime/floor_calibration.json`입니다. 재실행 때는 자동 적용하지 않습니다.
설치가 그대로일 때만 `저장된 보정 사용`을 누르세요. 카메라의 미세한 이동·회전,
바닥 기준점·치수, 해상도, 아이패드 화면 높이가 바뀌면 새로 보정합니다.
같은 카메라가 움직인 것은 프로그램이 자동으로 알아낼 수 없습니다.

### 보정 오류가 나올 때

- `아이패드 높이 ... 너무 높습니다`: 아이패드 화면 높이와 추정 카메라 높이를
  따로 표시합니다. 카메라 설치 높이를 입력했다면 바닥부터 아이패드 화면까지
  실측한 미터 값으로 바꾸세요. 높이 입력 오류는 회전 행렬 오류와 구분합니다.
- `보정 오차 ... 허용 4px 초과`: 바닥에 줄자로 잰 직사각형 네 모서리를 표시하고
  그 위치를 클릭해야 합니다. 영상에서 보기 좋은 네모를 임의로 그리는 방식이
  아닙니다. 카메라가 기울어져 있으면 실제 직사각형도 영상에서는 사다리꼴처럼
  보일 수 있습니다. 가로·세로 치수와 실제 변의 대응을 확인하세요.
- `카메라 회전・이동 행렬`: 보정 데이터 자체의 회전·이동 값 검증 실패입니다.
  정상적인 높이 입력 오류와 별개입니다.

반복 설치 시에는 [바닥 마커 자동 보정](FLOOR_MARKER_SETUP.md)을 사용하세요.
바닥 기준 마커의 중심 간 거리와 인쇄한 검은 변 길이는 실측해야 합니다.

## 4. 실제 로봇 제어

미리보기 창을 닫고 다음으로 실행합니다. 노트북과 청소기는 서로 통신 가능한
동일 로컬 네트워크에 있어야 합니다. 토큰은 콘솔에서 입력하며 저장하지 않습니다.

```powershell
$vacuumIp = Read-Host "청소기 IPv4 주소"
.\.venv-camera\Scripts\python.exe navigation_app.py --drive --ip $vacuumIp
```

보정을 새로 하거나 유효한 저장 보정을 불러오고, 로봇 위치·방향과 경로를 확인합니다.
넓게 비운 구역에서 가까운 목표점을 정한 뒤 **`실물 주행 시작`**을 누릅니다.
수동 모드 진입 후 약 5초 준비 시간이 있습니다. 기본 전진 속도는 최대 0.08m/s,
회전은 최대 30도/초입니다. 500ms 길이의 이동 명령을 최소 300ms 간격으로 갱신합니다.
출발 전 상태 조회가 시간 초과되면 조회만 한 번 더 시도합니다.
이동 응답이 한 번 빠지면 상태를 한 번 조회해 수동 모드를 확인한 뒤 최신 경로 명령을
사용합니다. 상태 조회가 실패하거나 이동 응답이 연속으로 빠지면 정지합니다.

- 로봇 근처와 지도 안쪽의 여러 칸에 걸친 장애물은 바로 반영합니다. 먼 지도
  가장자리는 여러 칸에 걸친 검출을 두 프레임, 고립된 검출을 세 프레임에서 확인합니다.
  확정한 장애물은 해당 위치에 평평한 바닥이 1.2초 동안 관측된 뒤 해제합니다.
- `정지` 또는 **Esc**: 주행 중단과 정지 명령을 요청합니다.
- 새 장애물이 경로를 막으면 정지 요청을 보내고 기존 경로를 취소합니다. 정지 명령
  응답과 태그 위치 안정 확인 후 같은 목표의 경로를 다시 계산합니다. 우회로가
  생기면 이어서 이동하고, 경로가 없으면 정지한 상태로 기다립니다.
- 마커·깊이 측정 실패, 영상 지연 시 정지합니다. 측정이 복구되어도 사용자가
  시작을 다시 눌러야 합니다. 통신 오류는 프로그램을 재실행해야 해제됩니다.
  로봇 위치를 확인하지 못한 프레임은 로봇 몸체가 장애물로 저장되지 않도록 깊이
  지도에 넣지 않습니다. 이전 관측값의 유효 시간은 계속 줄어듭니다.
  최근에 마커가 잡혔다면 현재 프레임의 그 주변을 확대해 한 번 더 찾습니다.
  지도에 잠시 회색으로 표시하는 마지막 위치는 화면 안내에만 사용합니다.
- 깊이 영상은 프레임마다 격자로 읽는 픽셀의 위치를 바꿉니다. 유효한 깊이값으로
  확인하지 못한 지도 칸은 회색으로 남고 주행 경로에서 차단됩니다.
- 회전 방향이 반대여서 `회전 방향 불일치`가 표시되면 정지한 뒤
  `--turn-sign -1`을 추가해 재실행하고 짧은 회전부터 확인합니다.

프로그램은 관측 위치가 목표에서 12cm 이내이면 도착으로 표시합니다.
이는 실제 위치 보정 정확도나 WES의 상품 검증 완료를 보장하지 않습니다.

**이번 연속 제어 방식은 소프트웨어·모의 환경에서 검증했으며, 실물에서의
목표점 주행과 동적 회피는 아직 확인하지 않았습니다.** 이전에 성공한
`manual_control_once`와는 수동 모드를 유지하는 방식이 다릅니다.
첫 시험은 옆에서 본체 정지 버튼을 누를 수 있는 상태로 진행하세요.
Wi-Fi 단절·프로세스 강제 종료 때는 정지 요청 전달을 보장할 수 없습니다.
로봇 자체 센서의 자동 회피에 의존하지 않습니다. 낮거나 얇은 물체, 투명·반사 물체,
가려진 장애물과 빠르게 움직이는 사람은 깊이 지도만으로 확실히 검출할 수 없습니다.
자동 감지는 바닥 위 약 6cm 이상 물체를 대상으로 합니다.

정지 때마다 `runtime/stop_command_timing.csv`에 속도 0, 수동 모드 종료, 일시정지의
호출 시각·소요 시간·응답 여부가 기록됩니다. `responded`는 명령 호출의 응답 기록입니다.
수동 모드 종료 또는 일시정지가 시간 초과되면 기본 정지 명령을 모두 보낸 뒤
해당 정지 명령 중 하나를 한 번 더 시도합니다. 정지 중 일부 응답이 시간 초과되어도
수동 모드 종료와 일시정지 모두 응답하고 상태 조회에서 `Idle` 또는 `Paused`를 확인하면
정지 처리에 성공한 것으로 기록합니다. 정지 상태를 확인할 수 없으면 자동 주행이 잠깁니다.
바퀴가 정지했는지는 현장에서 확인하세요. `--measure-replan`을 함께 쓰면 기존 경로가
막힌 뒤 정지 대기와 경로 계산 시간도 `runtime/replan_timing_stop_first.csv`에 남습니다.
`runtime/drive_events.csv`에는 처음 정지를 요청한 이유와 이동 응답 누락, 연결 확인,
재시작이 필요한 오류가 기록됩니다.

## 5. 약 3m 높이의 최종 설치

```powershell
.\.venv-camera\Scripts\python.exe navigation_app.py --resolution 1280x720
```

고해상도에서 새로 보정하고, 전체 구역에서 마커가 지속 검출되는지 확인합니다.
하단 `마커 …px`는 검은 사각형의 가장 짧은 변 길이입니다. 24px 미만이면 주행을
허용하지 않으며, 그 이상도 인식 안정성을 보장하는 수치는 아닙니다.
아이패드에서 흰 여백을 남기면서 마커를 크게 표시하고 조명 반사를 줄이세요.
구역을 너무 넓히면 화면 가장자리에서 마커나 바닥이 가려질 수 있습니다.
높이만으로 사용 가능한 구역 크기를 확정하지 말고 영상과 지도에서 확인합니다.
검증 후 같은 해상도 옵션에 `--drive`를 추가해 실제로 제어합니다.

아이패드가 로봇 밖으로 돌출되면 `--robot-radius`에 로봇 중심부터 화면 모서리까지
포함하는 반경을 입력해야 합니다. 예: `--robot-radius 0.23 --clearance 0.15`.
주행 공간이 좁아서 경로가 안 생긴다는 이유로 실제 크기보다 작게 설정하지 마세요.
