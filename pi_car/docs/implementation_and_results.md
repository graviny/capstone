# 실차 자율주행 스택 구현 현황·원리·실험 결과

이 문서는 `feature/pi_car1`에서 작성한 `pi_car/`의 구현과 실제 D455 실험을 종합한다.
기존 Webots 코드와 독립적으로 구성했으며, 저장소 루트 README는 기존 내용으로 유지한다.
아래 수치는 저장된 실제 실험 JSON과 테스트 실행 결과에 근거한다.

## 1. 현재 완료 범위

**외부 PC에서 RGB-D 저장 → 바닥 좌표계 추정 → 지도 생성 → 태그 중심 좌표 계산 →
목표점 선택 → A* 경로 미리보기까지 확인했다.**

차량의 Raspberry Pi에 연결해 실제 자율주행한 단계는 아니다. Pi에서 사용할 계획·제어·
하드웨어 인터페이스를 작성했고, 실제 모터 주행은 기본 비활성으로 유지했다.

| 모듈 | 구현 내용 | 현재 검증 상태 |
| --- | --- | --- |
| Camera | D455 수신, RGB/Depth 정렬, 렌즈 보정, 캡처 저장, 프리뷰 | 실제 D455 RGB-D 수신·연속 스트림 확인 |
| Calibration | 실측 기준점 강체 정합, 바닥 ROI RANSAC 로컬 좌표계 | 로컬 평면 방식 실장 확인. 실측 기준점 방식은 장비 없는 테스트만 확인 |
| Mapping | 높이 기반 Free/Occupied/Unknown 격자, 파일/메타데이터 저장 | 실제 바닥·벽·주변 물체를 포함한 지도 생성 확인 |
| Localization | AprilTag 검출, Depth 중심 좌표, 실측 크기 기반 PnP 경로 | 실제 ID 16 검출·Depth 중심 확인. 실제 PnP 정확도 미평가 |
| Inspection | RGB/지도 표시, 픽셀 좌표 확인, 목표 저장, A* 미리보기 | 실제 캡처의 픽셀을 이벤트 처리에 입력해 끝까지 확인 |
| Global Planning | 4방향 A*, Unknown 차단, 차체 여유 확장 | 실제 캡처 지도에서 경로 생성. Pi 실행 시간·실차 추종 미측정 |
| Perception | 초음파 측정 모델, Adeept cm→m 어댑터 | 원본 코드 확인 및 가짜 모듈 테스트. 실제 초음파 연결 미검증 |
| Control | 경유점 방향 오차 기반 회전/전진 명령 계산 | 장비 없는 계산·정지 로직 테스트. 실제 주행 미검증 |
| Local Planning | 장애물 감지 시 정지하는 확장 지점 | 우회·경로 복귀·동적 지도 재탐색 미구현 |
| Hardware | 비활성 기본 드라이버, Adeept 모터·서보 어댑터 | 실물 모터/서보 구동 미검증 |
| Transport | Pose 모델, JSON Lines encode/decode | 직렬화 테스트. 실제 TCP 연결·지도 전송·상태 교환 미구현 |

## 2. 어떤 원리로 구현했는가

### 카메라 좌표와 바닥 좌표

RGB와 Depth를 동일한 영상 좌표로 정렬하고, RealSense SDK의 렌즈 모델로 보정한다.
실장 D455가 inverse Brown-Conrady 모델을 보고하는 문제를 발견해 SDK 투영 방식으로 수정했다.
보정된 픽셀과 optical depth로 `X=(u-cx)Z/fx`, `Y=(v-cy)Z/fy`를 계산한다.
강체 변환으로 카메라 XYZ를 바닥 좌표계로 옮긴다.

실측 기준점이 있으면 대응점의 SVD 강체 정합을 사용한다. 이번에는 실측값이 없어
바닥 ROI에서 RANSAC으로 평면을 구하고, 지지점을 SVD로 다시 맞춰 로컬 좌표계를 만들었다.
원점은 선택한 바닥 점들의 중앙 부근, +X는 카메라 오른쪽을 바닥에 투영한 방향이다.
따라서 카메라 위치와 ROI가 다른 실험끼리는 원점·축이 다를 수 있다.

### 지도와 장애물 확장

바닥과 가까운 높이의 관측이 충분하면 Free, 지정 높이 이상의 관측이 충분하면 Occupied,
깊이 구멍·가림·관측 부족은 Unknown으로 둔다. 같은 셀에서는 장애물을 우선한다.
현재는 단일 캡처·높이 임계값 기반 지도이며 Bayesian occupancy 갱신이나 SLAM은 아니다.
계획 시에는 원본 지도와 별도로 차체 반경·여유 및 격자 양자화 여유를 적용한다.
Unknown과 지도 밖도 막아 관측되지 않은 공간으로 경로가 나가지 않도록 한다.

### 태그 위치와 방향

OpenCV `ArucoDetector`에서 AprilTag 36h11 사전을 사용해 ID와 네 꼭짓점을 검출한다.
실측 변 길이를 알면 IPPE_SQUARE PnP를 사용할 수 있다.
이번 휴대폰 화면 태그는 변 길이를 몰라, 태그 내부 Depth 중앙값과 중심 픽셀로 XYZ를 구했다.
표시한 방향은 태그가 바닥과 평행하다고 가정한 근사치이며 차량 전방과 같다는 뜻은 아니다.

### 경로 계획과 제어

A*는 4방향 격자·이동 비용 1·맨해튼 거리 휴리스틱을 사용한다.
결과는 셀 중심 경유점이며 회전 비용이나 차량 운동학을 고려하지 않는다.
현재 경로는 PC에서 확인한 미리보기이고, Pi에서 같은 모듈을 사용할 구조다.
규칙 기반 추종은 방향 오차가 크면 회전하고 작으면 전진한다.
위치·통신·초음파가 무효면 정지를 우선한다. PID·Pure Pursuit는 아직 없다.

원논문·공식 사례·실제 코드의 대응과 발표 문장은 [algorithm_references.md](algorithm_references.md)에 정리했다.

## 3. 실험 환경과 절차

- 실제 RealSense D455, RGB/Depth 각각 640×480으로 진행했다.
- 카메라를 손으로 들고 촬영했으며, 실험 사이 위치가 바뀌었다.
- 각 실험은 새 캡처와 새 로컬 평면 보정을 사용했다. 이전 보정값을 재사용하지 않았다.
- 캡처 직후 카메라를 해제하고 이후 처리는 저장 영상으로 진행했다.
- 줄자로 측정한 위치·방향의 정답 데이터는 없었다.
- 차량은 구동하지 않았다. 20cm 차체 반경+여유는 실측값이 아닌 초기 가정이다.

### 4.3 실험 02: 실제 AprilTag 중심

| 항목 | 결과 |

| 셀 수 | Free 1334 / Occupied 222 / Unknown 667 |

일반 실험 보고서의 `apriltag_detected:false`는 해당 일반 실행에서 태그 검사기를 연결하지
않은 상태의 값이다. 별도 `tag_report.json`에서 ID 16을 실제로 검출했다.
실제 크기를 몰라 크기 기반 PnP를 실행하지 않았다. Depth 기반 크기 추정은 실측값을 대체하지 않는다.

### 4.4 `S(test)`와 실제 태그 위치가 달랐던 이유

`S(test)`는 경로 생성 확인용으로 자동 선정한 가상 출발점이다.
실험 02에서 시험 출발점은 (0.075,0.135)m, 태그는 (0.0462,0.5426)m로 약 40.9cm 떨어져 있다.
두 점을 같은 위치로 표시한 것이 아니다. 이후 같은 좌표계에서 태그를 출발점으로 경로를 재계산했다.
비교 화면은 `data/experiment_02/comparison.png`, 경로는 `tag_to_goal.json`에 저장했다.
또한 실험 01과 02는 서로 다른 로컬 좌표계이므로 좌표값을 그대로 비교하면 안 된다.

## 5. 성능에 대해 현재 말할 수 있는 것과 없는 것

**확인한 것:** 실제 RGB-D 수신, 바닥 평면 추정, 높이 기반 지도 생성,
실제 태그 ID와 Depth 중심 계산, 목표 저장, 격자 경로 생성이 동작했다.

**아직 평가하지 않은 것:** 독립 실측 위치·방향 오차, 지도 장애물 검출 정밀도/재현율,
태그의 시간적 흔들림·검출률, Pi A* 실행 시간, 전체 처리 지연,
실차 도착 오차·성공률·주행 시간·충돌·회피·경로 복귀 성공률.

특히 아래 수치를 정확도와 혼동하면 안 된다.

- 평면 RMS 2.75~3.23mm: 추정한 평면에 관측점이 얼마나 가까운지 나타내는 맞춤 잔차다.
  실제 위치 오차가 3mm 이내라는 뜻은 아니다.
- Depth 유효 비율: 값이 존재하는 비율이며 올바른 깊이인 비율이 아니다.
- 태그 내부 깊이 IQR 약 3mm: 한 영상에서 표면 내 깊이 분포이며 시간적 안정성/좌표 정확도가 아니다.
- 경로 길이: 해당 격자에서 계산된 길이이며 실제 주행 거리/도착 성공을 뜻하지 않는다.
- 단일 태그 검출: 한 장의 성공 사례이며 검출 성공률 100%라는 뜻은 아니다.

## 6. 자동 테스트

가장 최근 실행에서 `unittest` **14개 테스트가 통과**했다.
좌표 보정·깊이 매핑·원본 지도 저장/로드·장애물 확장·A*·목표 선택·태그 합성 영상·
실측 크기 없는 Depth 태그 검사·태그 소실·비정상 입력 시 정지를 포함한다.
이는 단위/통합 회귀 검사이며 실제 차량 성능시험이 아니다.

```bash
cd pi_car
MPLBACKEND=Agg python -m unittest discover -s tests -v
```

## 7. 카메라를 움직여도 되는 시점

저장된 캡처만 분석할 때는 촬영 완료 뒤 카메라를 옮겨도 된다.
지도를 저장했더라도 실시간 Localization에는 카메라→지도 변환이 계속 필요하므로
카메라를 고정해야 한다. 움직였다면 기존 지도 좌표가 알려진 기준점으로 다시 보정한다.
기준점 없이 RANSAC 로컬 좌표계를 새로 만들면 원점·축도 바뀌므로 기존 지도의
위치·목표 좌표를 그대로 사용할 수 없다.

## 8. 다음 실험과 남은 구현

1. 카메라를 고정하고 실측 기준점으로 공통 월드 좌표계를 만든다.
2. 크기를 측정한 큰 태그로 여러 위치·방향을 반복 촬영해 실측 오차를 평가한다.
3. 장시간 검출률·위치 흔들림·전체 지연을 기록한다.
4. PC↔Pi 통신과 지도·목표 전달을 연결하고 Pi에서 A* 실행 시간을 측정한다.
5. 초음파/서보 갱신 상태와 별도 모터 watchdog을 확인한 뒤 저속 주행을 연결한다.
6. 규칙 기반 경로 추종 → 정지 → 제한적 회피 → 경로 복귀를 단계별 검증한다.
7. 이후 동적 장애물 지도·재계획·PID·Pure Pursuit를 확장한다.
