# 2026-11-26 Pi Car 지도 촬영과 실차 제어 변경 기록

이번 작업의 기준은 PC의 `feature/pi_car1` 브랜치에 있던 `40503fb`다. RealSense로 실차 주행 구역을 다시 촬영한 뒤, 차량 1번의 직진·회전과 지도 클릭 주행을 검증했다. 차량에는 AprilTag 36h11 ID 42를 사용했다. 태그 검은 사각형의 한 변은 7cm다.

## 1. 지도 재촬영과 차량 연결

RealSense D455로 바닥을 세 번 촬영했다. 매번 3cm 격자와 20cm 차량 여유 거리를 적용했다.

| 촬영 | 유효 깊이 픽셀 | 주행 가능 셀 |
| --- | ---: | ---: |
| 첫 촬영 | 83.5% | 18개 |
| 두 번째 촬영 | 83.9% | 98개 |
| 세 번째 촬영 | 84.1% | 129개 |

세 번째 지도의 129개 셀은 모두 이어져 있다. 원본 지도는 39×32셀이고 크기는 1.17×0.96m다. 이 지도를 만들 때 적용한 여유 거리와 이후 실시간 깊이 영상에서 확인한 장애물 위치를 기준으로 시험 구간을 골랐다.

PC에서 Fleet 서버와 D455 위치 추적을 실행했다. 차량 Pi에는 같은 원본 지도 두 파일을 복사하고, 기본 Adeept 서비스의 GPIO 점유를 해제한 뒤 `robot-client`를 실행했다. PC와 Pi에서 `map.npy`와 `map_metadata.json`의 SHA-256이 일치하는 것을 확인했다. 차량 연결, 위치 추적, `STOPPED` 응답도 확인했다.

## 2. 직진 중 떨림, 속도, 목표 오차 개선

이전 추종기는 조향 오차가 약 0.25rad를 넘으면 전진에서 제자리 회전으로 즉시 전환했다. 짧은 직진 시험의 마지막 약 1.5cm에서 관측 오차가 이 기준을 오르내리면서 제어 방식이 반복해서 바뀌었다.

- 작은 각도 오차에는 좌우 바퀴의 출력 차로 대응한다. 큰 방향 변경에는 제자리 회전을 사용하고, 회전 시작과 종료에 서로 다른 기준을 사용한다.
- 마지막 목표에 가까워질 때만 출력을 낮춘다. 중간 경유점과 최종 목표의 허용 오차를 분리했다. 이번 3cm 지도에서 최종 도착 판정 반경은 1.35cm에서 1cm로 줄였다.
- Adeept의 `Move.Motor()`는 바퀴 하나에 출력할 때마다 공용 PCA9685의 주파수를 다시 설정한다. Pi에 설치된 드라이버에서 이 설정이 칩을 절전 상태로 전환하고 약 5ms 대기하는 것을 확인했다. 바퀴 네 개를 갱신할 때마다 이 동작이 반복됐다.
- `Move.setup()`에서 초기화한 각 모터의 `throttle`에 출력을 직접 전달하도록 바꿨다. 모터 방향의 부호와 네 바퀴 배치를 보존한다. 최종 실차 실행 옵션은 `--drive-output 0.30 --max-output 0.30`이었다.

세 시험 모두 전방 12cm를 목표로 한 짧은 직진이다. 소요 시간은 PC의 MOVE 명령부터 차량의 `ARRIVED` 응답까지이며, 거리와 오차는 카메라 위치를 기준으로 계산했다.

| 시험 | 순항 출력 | 도착 응답 | 관측 이동 거리 | 정지 후 목표 오차 |
| --- | ---: | ---: | ---: | ---: |
| 기존 추종기 | 0.20 | 12.28초 | 10.67cm | 1.39cm |
| 조향과 감속 개선 | 0.25 | 8.78초 | 11.16cm | 0.87cm |
| PWM 재설정 제거와 출력 변경 | 0.30 | 1.11초 | 12.81cm | 0.81cm |

마지막 비교에는 PWM 처리와 출력 설정 변경이 함께 들어갔다. 세 시험 모두 `ARRIVED` 이후 `STOPPED` 응답을 확인했다. 로그 폴더는 각각 `straight_trial`, `smooth_straight_trial`, `pwm_straight_trial`이다.

## 3. 좌우 회전과 각도 명령

처음에는 같은 30% 출력으로 각 방향에 최대 2초의 회전 시험을 했다. 카메라에서 왼쪽 약 15°, 오른쪽 약 25°가 관측됐다. 별도의 지도 클릭 시험에서는 왼쪽으로 약 53° 진행한 뒤 회전각이 거의 변하지 않았다. 이때 위치 추적과 연결은 유지됐다. 개별 바퀴의 접지력과 토크는 측정 범위에 포함되지 않았다.

이를 바탕으로 현재 방향을 기준으로 부호 있는 각도를 받는 `TURN` 명령을 추가했다. 양수는 왼쪽, 음수는 오른쪽이며, 각도의 크기는 180°까지 입력할 수 있다. Pi가 회전 중 매번 카메라 방향을 읽고 목표 부근에서 감속·제동한다. 목표를 지나치면 보정 출력을 낮추고, 각도에 더 이상 진전이 없으면 `TURN_STALLED`를 보고한다. 정지 후 각도가 허용 범위에 들어오면 `TURN_REACHED`와 관측 각도 `turned_degrees`를 반환한다.

| 실차 명령 | Pi가 보고한 회전량 | 명령부터 완료까지 |
| --- | ---: | ---: |
| 왼쪽 25° | 24.43° | 2.93초 |
| 오른쪽 25° | 23.71° | 2.27초 |

이 결과는 촬영된 태그를 이용한 각도 추정이다. 동일 출력에서 두 방향의 회전 시간은 달랐고, 최종 보고 각도 크기 차이는 약 0.72°였다.

## 4. 위치 전달과 지도 클릭 창

- PC와 Pi 사이에 약 30ms의 시각 차이가 관측됐다. Pi가 갓 촬영한 프레임을 미래 시각으로 볼 수 있었다. PC 서버에 `--minimum-pose-age-ms` 옵션을 추가했고 실차 서버에는 50ms를 지정했다. 촬영 시각을 보존하고 300ms 위치 유효 기준을 적용한다.
- 지도 창에서 `Degrees`를 입력하고 `Turn left` 또는 `Turn right`를 누르면 제자리 회전을 보낸다. 지도 흰색 칸을 좌클릭하면 칸 중심으로 이동 명령을 보낸다. `STOP selected` 또는 `Esc`는 정지 명령을 보낸다.
- `Selected robot has no fresh valid pose`를 조사할 때 서버는 51~82ms 전 위치를 가지고 있었지만, 화면에 저장된 값은 클릭 시 약 340ms까지 오래된 경우가 있었다. 이동 클릭이나 회전 버튼 입력이 들어오면 서버에서 현재 위치를 다시 조회한 뒤 명령을 생성한다. 화면 갱신 간격도 150ms에서 100ms로 줄였다.
- 실제 위치가 사라진 상황에서는 새 명령을 거부한다. 이전 화면 위치를 일부러 오래되게 만든 테스트에서는 서버의 새 위치로 클릭 명령이 정상 실행됐다.

## 5. 초음파 입력 오류 진단과 수정

`ULTRASONIC_INPUT_INVALID` 발생 뒤 차량을 정지하고 Pi의 초음파 신호를 확인했다. 정상 거리값 사이에 2m 상한으로 잘린 값이 110회 중 6회 있었다. 상한값 때문에 정상 측정 간격이 가장 크게 벌어진 경우도 약 150ms였다. 이전 코드는 상한값 하나가 들어오는 즉시 직전 정상값을 지웠다.

수정한 실행기는 단발 상한값이 들어오면 마지막 정상 거리와 **원래 측정 시각**을 유지한다. 두 번 연속 상한에 걸리거나 반사 신호가 없으면 거리를 무효화한다. 유효한 정면 거리 **40cm 이하**와 마지막 정상 측정 후 **200ms 초과**는 정지 조건이다. 위치·통신·모터 watchdog도 적용한다.

Pi 적용 후 정지 상태에서 9초 동안 다시 측정했다. 원시 측정 127회가 모두 정상 범위였다. 단발 상한값의 타임스탬프 보존, 연속 상한값의 무효화와 새 근거리 측정으로의 교체는 회귀 테스트로 검증했다. 원인 재현과 재측정 기록은 `drive_check/ultrasonic-diagnostic.txt`, `drive_check/ultrasonic-fix-validation.txt`에 있다.

## 7. 새 브랜치의 카메라 클릭 주행

`feature/picar-b-four-wheel`에서 PC/Pi가 같은 코드를 쓰도록 Pi에 별도 worktree
`~/robotics/capstone-picar-b-four-wheel`을 만들었다. PC의 기존 브랜치와 Pi 원래 작업
폴더는 보존했다. PC의 내부 지도
`data/session_20261126/map_manual_01_filtered/clearance_05/map/`를 Pi worktree의
`pi_car/data/live_goal_map/`에 복사하고 두 지도 파일의 SHA-256 일치를 확인했다.

`fleet-panel --camera-dir <snapshot-dir> --calibration <calibration.json>`은
Fleet 서버의 최신 RGB-D 장면을 화면에 표시한다. 바닥을 좌클릭하면 픽셀의 깊이와
높이를 확인하고, 현재 카메라 보정으로 월드 좌표에 변환해 MOVE 명령을 보낸다.
PC/Pi에는 같은 내부 지도가 필요하지만 사용자는 지도 창 대신 카메라 영상을 클릭한다.
카메라를 두 프로세스가 동시에 열지 않도록 Fleet 서버가 약 4Hz로 장면을 저장한다.

차량 태그는 12cm 검은 변의 `ArUco 4x4 ID 1`로 교체됐다. 기존 7cm AprilTag는
천장 카메라의 640×480 장면에서 검출되지 않았다. 새 태그는 연속 10프레임 모두
검출됐고 위치 유효 기준을 통과했다. 새 태그의 인쇄 방향이 달라
`heading_offset_rad`를 `+π/2`로 변경했다. 화면 화살표가 차량 앞쪽을 가리키는지
확인한 뒤 실차 주행을 진행했다.

판을 치운 상태에서는 Pi 초음파 원시값이 30회 연속 2m 상한에 닿아 기존 안전
판정이 `ULTRASONIC_INPUT_INVALID`로 주행을 막았다. `robot-client --allow-no-echo`는
반복해 들어오는 **신선한 2m 상한값**을 열린 공간으로 해석한다. 2m 이내 거리값이
들어오면 초음파 정지 조건을 다시 적용하며, 센서 갱신이 멈추거나 `None`을 내면
정지한다. 기본 실행은 기존 무효 판정을 유지한다. 초음파 단선도 2m 상한으로
보일 수 있으므로, 이 옵션의 주행은 카메라에서 확인한 열린 바닥에서만 사용한다.

실차에서 `--max-output 0.30 --drive-output 0.30 --allow-no-echo`로 차량 앞쪽
약 16cm 목표를 보냈다. 카메라 위치는 `(-0.625,-0.685)m`에서
`(-0.743,-0.553)m`로 이동했다. 목표 `(-0.735,-0.555)m`과의 최종 카메라
오차는 약 0.8cm였고, PC 저널에는 `ARRIVED / GOAL_REACHED`가 기록됐다.
추가 STOP에도 `STOPPED`를 확인했다. 물체를 새로 놓아 초음파가 자동으로
근거리 값을 받아 정지하는 실차 시험은 이 단계에서 수행하지 않았다.

PC 전체 테스트는 70개 실행, 69개 통과, 선택 GPIO Zero 테스트 1개 생략이었다.
카메라 바닥 클릭 변환, 두 태그 사전의 독립 검출, 새 2m 상한의 시각 보존과
실제 30cm 측정으로의 자동 전환을 포함한다.
